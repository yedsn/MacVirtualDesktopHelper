## Context

现有基础只包含技术原型，不具有完整 Windows 行为。Feature-parity.md 是追踪依据，来源源码是每个交互的核对依据。

## Decisions

1. 使用原生 Swift/AppKit，保留现有 SkyLight/AX 桥接，避免改换技术栈丢失已验证能力。后续按窗口目录、桌面切换、窗口操作、规则状态、规则匹配、快照、备份、快捷键、界面拆分。
2. 菜单栏默认每桌面一个图标。卡片概览与 Windows 保持相同操作顺序，采用系统字体、语义色、原生焦点及弹窗。
3. Application Support/MacVirtualDesktopHelper 保存版本化设置和统一规则状态。修改先校验，再原子替换；导入必须在替换前整体验证并支持失败回滚。
4. 稳定应用身份以 Bundle ID/应用路径为主，标题精确或正则作区分；运行时 PID/CGWindowID 仅用于本次操作和重验，不作为便携身份。正则执行需要超时或等价的资源限制，避免卡死主线程。
5. 更新规则保留用户编辑字段，只对双向唯一匹配更新目标；应用规则独立预览且重验。歧义、已关闭、未知归属、缺失目标均报告并跳过。
6. 清理串行处理跨桌面窗口，执行前重新检查锁定；快照恢复只替换两套规则，绝不隐式归位。自动快照独立于窗口可见性。
7. 新 Bundle ID 单独验证权限。直达快捷键读取系统配置且配对释放修饰键；后续兼容性结论必须由新项目实测支持。

## Risks

私有 API 版本变化、Space 顺序变化、多屏/全屏行为、权限改变以及 Windows 身份字段不可移植。将不可支持项显式显示，禁止伪造成功。先完成当前单显示器功能，再记录和处理兼容性差异；不删减全量功能对照。

## Validation

原型来源记录仅说明技术来源。新项目需独立验证构建、身份、权限、真实点击及临时窗口操作；规则/备份/调度测试使用隔离数据。最终逐项完成 Feature-parity.md 的交互验收。
